# Голосовая справка Шерпы — ТЗ

Статус: одобрено 13.11.2026, реализовано 14.11.2026 — см. раздел «Как реализовано» в конце.
Решения приняты в разговоре 13.11 (вопросы 1–8 из `голосовая-справка.canvas`).

## Что получает пользователь

1. Двойной клик по псу → рядом с ним открывается окно «Спросить Шерпу».
2. «● Записать» (или пробел) → пёс в позе `look` («слушает»), на кнопке таймер. «■ Стоп» (или пробел) → конец. Лимит 60 с, на 60-й секунде запись останавливается сама.
3. Пёс в позе `think`, мозг расшифровывает речь локально (GigaAM). Текст появляется в поле, его можно поправить.
4. «Спросить» (Enter) → вопрос уходит в нейронку через OpenRouter, пёс `think`. Ответ появляется в окне, пёс машет (`wave`).
5. Кнопки: «Копировать», «Спросить ещё» (новая запись в том же диалоге). Закрыл окно → диалог окончен, следующий начнётся с чистого листа.
6. Каждый вопрос и ответ пишется в историю. Меню пса (ПКМ) → «История…»: последние запросы, токены и $ за сегодня и за месяц.

Без голоса: ответ только текстом.

| # | Вопрос | Решение |

| 7 | Аудио | Хранить последние 50 записей |
| 8 | Запуск | Два процесса; пёс сам запускает мозг, если тот не отвечает |

Цены на 13.11 (публичный `GET https://openrouter.ai/api/v1/models`), $ за миллион токенов, вход / выход:
`deepseek/deepseek-v4-flash` 0,09 / 0,18; `anthropic/claude-haiku-5.5` 0,10 / 0,50; `google/gemini-2.5-flash-lite` 0,10 / 0,40.

### Длинные записи: нарезка по паузам (Silero VAD)

Зачем. GigaAM рассчитан на аудио до 25 с (официальный README). Запись у нас до 60 с, поэтому целиком её отдавать нельзя.

Что измерено 13.11 на этой машине (одна запись 70,4 с с чтением текста, 138 слов в эталоне, файлы `test-audio/`; ошибки в словах без регистра и знаков):

| Способ | Кусков | Ошибок |
|---|---|---|
| Целиком | 1 | 21,7% (текст не обрезался, но в конце появились искажения) |
| Резка по самому тихому месту | 5 | 14,5% |
| VAD, порог 0,5, пауза 0,5 с | 8 | 15,2% |
| VAD, порог 0,5, пауза 0,3 с | 11 | 17,4% |
| **VAD, порог 0,4, пауза 0,8 с (выбрано 14.11)** | 3 | 14,5% |

Выводы: любая нарезка лучше, чем целиком; VAD точнее простой резки не стал, но выкидывает тишину и держит куски в лимите; слишком короткие куски (около 11) дают больше ошибок. Одна запись и один диктор, поэтому разницу в 1–4 слова за значимую не считаем.

Как работает.
1. `/transcribe` получает WAV, приводит к `float32`, 16 кГц.
2. `sherpa_onnx.VoiceActivityDetector` с `silero_vad.onnx` и настройками из `[vad]` режет запись на куски речи. Окно 512 отсчётов (32 мс). Замеры: VAD 0,52 с на 70 с записи (около 0,24 мс на окно), весит 2,3 МБ.
3. Каждый кусок идёт в `OfflineRecognizer` отдельным потоком данных. Тексты склеиваются через пробел в порядке времени.
4. Нет ни одного куска речи (тишина) → ответ `{"text": "", …}`, нейронку не вызываем, пёс показывает «Не расслышал, повтори».
5. Если VAD не удалось загрузить, запись режется на куски по 20 с с поиском самого тихого места в окне 12–20 с (как в тесте), и в лог пишется предупреждение.

Источник модели: `https://github.com/snakers4/silero-vad/raw/v5.0/files/silero_vad.onnx`, SHA-256 `6b99cbfd39246b6706f98ec13c7c50c6b299181f2474fa05cbc8046acc274396`. Файл кладётся в `brain/models/` вручную, мозг сам ничего не скачивает. Лицензию проверить до коммита файла.

Системный промпт (стартовый, правится в конфиге):
> Ты — Шерпа, робопёс-помощник. Отвечай по-русски, коротко, как справка: 2–6 предложений или короткий список. Вопрос получен распознаванием речи: он без пунктуации и может содержать ошибки в словах — пойми по смыслу. Если вопрос неясен — задай один уточняющий вопрос.

### Протокол пёс ↔ мозг (JSON, кроме `/transcribe`)

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /health` | — | `{"ok": true, "stt_loaded": false, "model": "deepseek/deepseek-v4-flash"}` |
| `POST /transcribe` | WAV PCM16 16 кГц моно, `Content-Type: audio/wav`, ≤ 60 с и ≤ 4 МиБ | `{"audio_id": "20261113-221530-ab12", "text": "…", "audio_sec": 4.2, "stt_ms": 610}` |
| `POST /ask` | `{"session_id": null \| "…", "question": "…", "transcript_raw": "…", "audio_id": "…", "audio_sec": 4.2, "stt_ms": 610, "source": "pet"}` | `{"session_id": "…", "answer": "…", "model": "…", "tokens_in": 512, "tokens_out": 180, "cost_usd": 0.00008, "llm_ms": 1900}` |
| `GET /history?limit=50` | — | список строк из `requests` (без `messages_json`) |
| `GET /stats` | — | `{"today": {"requests": 3, "tokens_in": …, "tokens_out": …, "cost_usd": …, "limit_usd": 0.5}, "week": {…}, "days30": {…}, "all": {…}, "reset_at": null}` (счётчики считаются с последнего сброса) |
| `POST /stats/reset` | — | обнуляет счётчики расхода (история остаётся), ответ как у `GET /stats` |
| `POST /settings/check` | `{"provider", "model", "api_key"?}` | бесплатная проверка без сохранения: `{"model_ok", "key_ok", "has_key"}` |

Ошибки: `{"error": "<код>", "message": "<по-русски для окна>"}` с HTTP-кодом. Коды: `no_api_key` (500), `daily_limit` (429), `audio_too_long` (413), `bad_audio` (400), `llm_failed` (502), `stt_failed` (500).

`session_id = null` → новый диалог. Мозг собирает историю диалога из `messages_json` строк этой сессии (переживает перезапуск мозга), берёт последние 6 пар.

Лимит: перед вызовом нейронки мозг суммирует `cost_usd` за сегодня (локальная дата). Если сумма ≥ `daily_limit_usd`, мозг отвечает `daily_limit` и пишет строку со `status='limit'`, нейронку не вызывает. Последний запрос может немного перешагнуть лимит — это допустимо.

Токены и стоимость: по документации Pydantic AI (context7, 13.11; не запускал) в версии 2.x `result.usage` — **свойство**, а не метод `usage()`, как было в черновике канваса. Стоимость OpenRouter приходит в `provider_details['cost']` ответа модели, если включён `openrouter_usage={'include': True}`. Оба места проверяем на этапе 0 на установленной версии. Если стоимость не пришла, пишем `cost_usd = NULL`, а лимит считаем по ценам из `/api/v1/models`, закэшированным при старте.

### Схема истории — `brain/data/brain.db`

```sql
CREATE TABLE requests (
  id             INTEGER PRIMARY KEY,
  created_at     TEXT    NOT NULL,          -- ISO 8601, локальное время
  session_id     TEXT    NOT NULL,
  turn           INTEGER NOT NULL,          -- 1, 2, … внутри сессии
  source         TEXT    NOT NULL DEFAULT 'pet',  -- pet / telegram / cli
  audio_file     TEXT,                      -- имя в data/audio/, NULL если удалено или не было
  audio_sec      REAL,
  transcript_raw TEXT,                      -- как выдал GigaAM
  question       TEXT    NOT NULL,          -- после правки пользователем
  answer         TEXT,
  model          TEXT,
  tokens_in      INTEGER,
  tokens_out     INTEGER,
  cost_usd       REAL,
  stt_ms         INTEGER,
  llm_ms         INTEGER,
  status         TEXT    NOT NULL,          -- ok / error / limit
  error          TEXT,
  messages_json  TEXT                       -- result.new_messages_json(): для продолжения диалога
);
CREATE INDEX requests_created ON requests(created_at);
CREATE INDEX requests_session ON requests(session_id, turn);
```

Аудио: при каждом `/transcribe` файл сохраняется как `data/audio/<audio_id>.wav`; самые старые сверх 50 удаляются, а их `audio_file` в базе ставится в `NULL`.

### Пёс — изменения в `sherpa_pet.py`

1. **Двойной клик.** `on_release` при коротком клике не запускает реакцию сразу, а ставит её через `root.after(250, …)` и запоминает id. Новый `bind("<Double-Button-1>")` отменяет отложенную реакцию (`after_cancel`) и открывает окно. Перетаскивание и падение не меняются.
2. **`VoiceWindow`** (`Toplevel`, поверх всех окон, рядом с псом, не выходит за рабочую область): кнопка записи с таймером, поле текста вопроса (`Text`, редактируемое), «Спросить», область ответа с прокруткой, «Копировать», «Спросить ещё», строка статуса для ошибок. Окно единственное: повторный двойной клик поднимает уже открытое.
3. **Запись** — `sounddevice.InputStream(samplerate=16000, channels=1, dtype='int16')`. Колбэк складывает куски в `queue`, WAV собирается в памяти (`wave` + `io.BytesIO`). Нет микрофона → сообщение в строке статуса.
4. **Сеть** — `urllib.request` (stdlib) в рабочем потоке. Результат кладётся в `queue.Queue`, а `tick()` или `after(50)` разбирает её в главном потоке. Tk трогается только из главного потока.
5. **Позы** — используем существующие: запись → `look`, расшифровка и ожидание ответа → `think`, ответ → `wave` на 3 с. Позы держатся через `temp_override_until`, как сейчас при клике. Новых спрайтов не рисуем.
6. **Запуск мозга.** Перед первым запросом `GET /health` с таймаутом 0,5 с. Не ответил → `subprocess.Popen([pythonw, "-m", "brain"], cwd=<проект>, creationflags=CREATE_NO_WINDOW)` и опрос `/health` раз в 300 мс до 15 с. Не поднялся → «Мозг не запустился, смотри brain/data/brain.log».
7. **Меню** — пункт «История…»: окно с таблицей последних 50 запросов (время, вопрос, начало ответа, токены, $) и строкой четырьмя карточками «Сегодня (с лимитом) / 7 дней / 30 дней / Всё время» и ссылкой «Сбросить счётчик расхода» (обнуляет только счётчики, не историю и не дневной лимит). Двойной клик по строке показывает полный ответ.

## Как реализовано (14.11.2026)

Отличия от плана выше и что выяснилось по ходу:

- **Окна** — в `sherpa_voice_ui.py`: карточка без рамки со скруглёнными углами в палитре пса, аватар в шапке меняет позу (слушает → думает → машет), круглый микрофон пульсирует красным при записи, ответы блоками как в чате, кнопки «Копировать», «Новая тема», значок истории. «История» — карточки «Сегодня / 7 дней / 30 дней / Всё время» и таблица; двойной клик по строке — подробности. Запись, клиент мозга и фоновые задачи — в `sherpa_voice.py`.
- **Распознавание**: Silero VAD съедал тихое первое слово («ну»), поэтому к каждому куску добавляются поля по 0,25 с. Замер на `test-audio/`: 70 с — 15,9% ошибок в словах, первые 60 с — 16,4%.
- **Нарезка VAD**: 14.11 по решению пользователя взяты порог 0,4 и пауза 0,8 с (в замере 13.11 — 3 куска, 14,5% ошибок против 15,2% у 0,5/0,5).
- **Нейронка**: `max_answer_tokens` поднят с 400 до 1000 — ответ со списком не влезал в 400 и падал с `OutputTokenLimitExceeded`. Рассуждения модели отключены (`openrouter_reasoning={'enabled': False}`).
- **Токены и стоимость** проверены на pydantic-ai 2.68.0: `result.usage` — свойство, стоимость — `provider_details['cost']`.
- **Запуск мозга**: ждём до 30 с (холодный старт с диска был 10,9 с, обычный — около 4 с); если процесс упал при старте — ошибка сразу.
- Под `pythonw` мозг выставляет `PYDANTIC_AI_NO_BANNER=1`: иначе Pydantic AI печатает баннер в отсутствующий stdout.

Не проверено автоматически: живой голос с микрофона от начала до ответа и двойной клик рукой (клики проверялись событиями Tk, запись — отдельно, распознавание — на файлах).

## Настройки нейронки (14.11.2026)

- Окно «Настройки» (`SettingsWindow` в `sherpa_voice_ui.py`): провайдер (выпадающий список, пока только OpenRouter — `PROVIDERS` в `brain/config.py`), модель, ключ API с глазком. Открывается шестерёнкой в шапке окна справки и пунктом меню пса «Настройки нейронки…».
- Мозг: `GET /settings` → `{provider, providers, model, key_source}`, где `key_source` — `windows`, `env` или `null`. `POST /settings` `{provider, model, api_key?, clear_key?}`: бесплатная проверка (список моделей `/api/v1/models`, ключ — `/api/v1/key`), при неверном ключе 400 `bad_key`, при несуществующей модели 400 `bad_model`, иначе сохраняет и пересобирает агента.
- Ключ: `brain/keystore.py`, диспетчер учётных данных Windows (keyring, служба «Sherpa brain»), запасной путь — переменная `OPENROUTER_API_KEY`. Сохранённый в Windows ключ важнее переменной. В `config.toml`, базу и лог ключ не попадает.
- Провайдер и модель: `save_settings()` меняет строки `provider` и `model` в верхней части `config.toml`, не трогая комментарии и `[gigaam] model`.
- Проверено 14.11: неверный ключ → 400 `bad_key`, несуществующая модель → 400 `bad_model`, сохранение текущей модели с ключом из переменной → `model_ok: true, key_ok: true`; в `brain.log` нет ни одной строки с ключом (`grep -c "sk-or"` → 0). Сохранение настоящего ключа в Windows через окно не проверялось — проверялась запись и удаление тестовой записи `sherpa-test`.
